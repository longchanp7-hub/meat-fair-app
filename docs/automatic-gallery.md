# 自動ギャラリー（縦型スマホ／折りたたみタブレット）

## 更新経路
既存の毎日09:00 JSTの更新と手動更新で、`npm run update` がフェア収集に続いて公式画像を収集します。
`app/data/gallery.json` に画像URL、元ページ、リンク先、画像寸法、種類、親フェアID・内容ハッシュ、確認時刻を出力します。PWAのID／スコープ、Service Worker、既存の開催期間判定は変更しません。

## 画像の区別
- campaign: 公開審査を通ったフェアのメイン画像。
- detail: 同じ公式フェアページ内で明確な商品名を持つ補助画像。親フェアが消えたり内容ハッシュが変われば表示しません。
- menu: 公式トップページに実際に掲載されているランチ・宴会などの画像付きリンク。「公式メニュー・関連情報」と表示し、フェア件数に含めません。開催日不明の独立イベントを開催中に見せることはしません。

公式HTMLに存在する画像だけを採用。デスクトップ版とスマホ版の重複、ロゴ、ボタン、料金表、求人、子供・学生向け情報などを除外します。写真や価格を生成したり、推測した画像パスを作りません。
商品名の文字画像と料理写真が分離した公式ページでは、同じディレクトリ・商品識別子の画像を照合します。例えばHTMLに実在する `menu01_pic` と `menu01_text`／`menu01_sign` の組なら、商品名は文字画像の公式alt属性から、画像URLは実在する料理写真から取得します。対応写真がない、商品名が曖昧、別ページへのリンク内にある場合は推測しません。タイトル・看板・価格だけの画像を独立した料理写真枠にはしません。
メイン画像→フェア内の料理→関連ランチ→宴会メニューの順を基本にします。画像収集にも固定8枚打ち切りを置かず、掲載確認・重複排除・寸法検証を通った件数を配置へ渡します。

## 自動配置
`gallery-plan.mjs` はチェーン名に依存しない共通エンジンです。画像の縦横比・優先度・カードの実幅から、縦積み、均等／不均等な横並び、メイン＋補助画像群を比較します。長方形を隙間なく分割し、画像は元の比率で表示。価格や文字を切り取るトリミングはしません。
縦型スマホが主軸です。Foldを開いた幅やタブレットでも同じエンジンで再計算し、PC専用の固定カラムを前提にしません。
表示中の画面も、前面に戻ったとき（前回取得から1分以上）と前面表示中5分ごとに公開データを読み直します。
固定の4枚上限や空き枠はありません。表示対象の数だけブロックを作成し、増減・タブ切替・端末の開閉・画面回転の際に再配置します。読みやすさのため6pxの間隔と56pxの説明帯は残します。画像自体に含まれる余白は、情報保護のため削りません。

縦型スマホでは可読性を優先するため、タブレットで横並びになる補助画像が縦に並んだり、メイン画像の下へ回り込んだりします。すべての端末に同じ固定2×2枠を押し付けません。画像追加のためにフェア件数を水増しすることもありません。

## 障害時
補助画像／メニューの前回データは確認時刻を更新せず最大48時間まで。正常取得時は掲載終了したメニューを次回更新で取り除きます。公式サイトの構造変更・取得制限・曖昧な画像は `gallery.json` の `errors` に記録し、不明な内容を捏造しません。公式の未掲載・JavaScript専用ページなどを完全に検出する保証はありません。
画像読み込み失敗時は該当ブロックを除去して再配置し、元ページへのリンクを残します。ギャラリーデータが取れなくても既存フェアのメイン画像で表示を継続します。

## 検証
`tests/gallery-dynamic-growth.test.mjs` で画像0〜40枚・11種類の幅（280/320/360/390/430/600/690/720/760/820/1024px）・11種類の縦横比の組み合わせを検証します。実際の全15チェーンの公式画像寸法も合わせ、現在のデータでは5,126通りの配置について、ブロック数、順序、縦横比、重なり、枠外へのはみ出し、右端・下端の空白帯を確認します。フェアが0→1→2→5→12→40→7→3→0→6件と増減しても、削除済みのフェアの補助画像を残さず、公式ページの内容変更時には古い補助画像を外すことも確認します。これらのテストは今後の更新時にも `npm test` で実行されます。

既存の0〜16枚・9種類の幅の試験に加え、19枚の増加ケースも検証します。写真／文字画像の組み合わせ、曖昧な名前、別ページの混入、文字画像のみ、8件を超える関連メニューを回帰テストします。
実ブラウザ試験は360/390/430/690/820/1024pxで15ブランドの画像配置を確認します。390/820pxでは全タブ・全ブランドの絞り込みも操作し、画像の重なり／切れ／歪み、横はみ出し、失敗時の再配置、PWAスコープを確認します。
`gallery-live-resize.cjs` は取得済みの公式画像をテスト用DOMに表示し、0→1→2→複数→減少→0→再追加を同一セッションで試験します。さらにDOMを保持して390→820→390→690→1024→360pxと変化させ、Foldの開閉に相当する再配置を検証します。テスト用DOMは試験終了時に削除され、公開データは変更しません。
実機のAndroid WebAPKインストールをブラウザ試験で代用したとは扱いません。
プレビューは `layout/**` ブランチまたはPRで実行し、公開せず画像付きレポートを保存します。
