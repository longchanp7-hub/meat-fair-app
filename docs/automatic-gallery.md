# 自動ギャラリー（縦型スマホ／折りたたみタブレット）

## 更新経路
既存の毎日09:00 JSTの更新と手動更新で、`npm run update` がフェア収集に続いて公式画像を収集します。
`app/data/gallery.json` に画像URL、元ページ、リンク先、画像寸法、種類、親フェアID・内容ハッシュ、確認時刻を出力します。PWAのID／スコープ、Service Worker、既存の開催期間判定は変更しません。

## 画像の区別
- campaign: 公開審査を通ったフェアのメイン画像。
- detail: 同じ公式フェアページ内で明確な商品名を持つ補助画像。親フェアが消えたり内容ハッシュが変われば表示しません。
- menu: 公式トップページに実際に掲載されているランチ・宴会などの画像付きリンク。「公式メニュー・関連情報」と表示し、フェア件数に含めません。開催日不明の独立イベントを開催中に見せることはしません。

公式HTMLに存在する画像だけを採用。デスクトップ版とスマホ版の重複、ロゴ、ボタン、料金表、求人、子供・学生向け情報などを除外します。写真や価格を生成したり、推測した画像パスを作りません。

## 自動配置
`gallery-plan.mjs` はチェーン名に依存しない共通エンジンです。画像の縦横比・優先度・カードの実幅から、縦積み、均等／不均等な横並び、メイン＋補助画像群を比較します。長方形を隙間なく分割し、画像は元の比率で表示。価格や文字を切り取るトリミングはしません。
固定の4枚上限や空き枠はありません。表示対象の数だけブロックを作成し、増減・タブ切替・端末の開閉・画面回転の際に再配置します。読みやすさのため6pxの間隔と56pxの説明帯は残します。画像自体に含まれる余白は、情報保護のため削りません。

## 障害時
補助画像／メニューの前回データは確認時刻を更新せず最大48時間まで。正常取得時は掲載終了したメニューを次回更新で取り除きます。公式サイトの構造変更・取得制限・曖昧な画像は `gallery.json` の `errors` に記録し、不明な内容を捏造しません。公式の未掲載・JavaScript専用ページなどを完全に検出する保証はありません。
画像読み込み失敗時は該当ブロックを除去して再配置し、元ページへのリンクを残します。ギャラリーデータが取れなくても既存フェアのメイン画像で表示を継続します。

## 検証
純粋関数テストで0〜16枚、9種類の幅を検証。実ブラウザ試験は360/390/430/690/820/1024pxで全タブ・15ブランド・画像の重なり／切れ／歪み、横はみ出し、失敗時の再配置、PWAスコープを確認します。実機のAndroid WebAPKインストールをブラウザ試験で代用したとは扱いません。
プレビューは `layout/**` ブランチまたはPRで実行し、公開せず画像付きレポートを保存します。
