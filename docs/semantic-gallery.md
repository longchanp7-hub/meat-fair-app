# 意味に基づく自動ギャラリー — 仕上げ記録

## 2026-09-15: 意味の優先順位と補助画像の寿命
`gallery-semantics.mjs` が全ブランド共通で `group / priority / visualWeight` を付けます。
メインフェア → 肉・海鮮の食べ放題コース → 関連ランチ・宴会 → 個別料理の順とし、同じグループを優先してまとめます。
ブランド名や画像ファイル名をCSS・配置エンジンに埋め込みません。縦長メインの横に置く補助画像数もメタデータから決定します。
現在のしゃぶ葉では鴨しゃぶメインの右側に黒豚・和牛、その下にランチ・宴会が並び、個別料理は続く段へ配置されます。
390/430pxでは右側が縦積み、Fold相当では肉2枚の段と関連2枚の段に分かれます。極端に狭い画面や文字拡大時は価格・可読性を優先し、下へ回します。
横長フェア2枚はスマートフォンで縦積みする既存の比率判断を維持します。画像の切り取りはしません。
税込価格の実際の文字幅をブラウザで測定して、価格が欠ける幅の候補を除外します。

`gallery.json` の `policyVersion: 2` では、補助メニューにも元フェアの `parents: [{campaignId,parentHash}]`、取得元 `sourceUrl`、取得ページの `sourceHash`、`checkedAt` を記録します。
元フェアの削除・終了・証拠ハッシュ変更後は補助画像を表示しません。共有メニューは元の親フェアのいずれかが一致する間だけ有効です。
新しい無関係なフェアに古いメニューをブランド名だけで引き継ぎません。親を記録していない旧メニューは次の正常収集で再検証されるまで表示しません。
公式サイトの一時的な失敗時は、親の一致と確認から48時間以内という両条件を満たした前回画像だけを維持し、検証時刻は延長しません。

`gallery-semantics.test.mjs` は意味順・料金可読性・0〜40枚・親の増減・終了・ハッシュ変更・LKG期限を追加検証します。従来のテストは削除しません。
`refresh-lifecycle.cjs` は実ブラウザ内だけのレスポンス差し替えで、前面復帰 → 新フェアデータ反映 → ギャラリー取得失敗時の古い補助画像除去 → 元データの復元を、再読み込みなしで確認します。
390/820pxは全15ブランドの個別スクリーンショットと配置寸法を保存します。公開後の `public-files.json` には、公開URLから取得し照合に成功した全ファイルのSHA256を残します。
